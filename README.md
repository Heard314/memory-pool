# MemoryPool

## 声明

本项目基于【代码随想录知识星球】教学项目：Kama-memoryPool(https://programmercarl.com/other/kstar.html)
的v3版本。
主要完善了内存释放相关的一个问题：在多层缓存架构中，某一层内存块过多时，如何向下一层传递多余的内存；
除此之外，完善了各层的析构方法等，使该内存池项目的内存管理机制更加完善。


该项目的三层架构如下所示：
- 线程本地缓存（ThreadCache）：每个线程维护自己的内存块链表，减少线程间的锁竞争，提高内存分配效率。
- 中心缓存（CentralCache）：用于管理多个线程共享的内存块，支持批量分配和回收，优化内存利用率。
- 页面缓存（PageCache）：负责从操作系统申请和释放大块内存，支持内存块的合并和分割，减少内存碎片。

本次修改的主要亮点是：
根据三层缓存架构的特点，设计了一种内存向下传递机制，使得某一缓存层的空闲内存过于多时，能够向下一层进行传递，及时释放掉多余的空闲内存。
具体设计的机制如下所示：

（1）线程本地缓存->中心缓存：

线程本地缓存释放时机：当某一index下的内存块过多时，释放；其释放的单元是index下的单一内存块

中心缓存接收：中心缓存的内存来源于页面缓存，每次得到一个批量的页内存，并且该页批量只会用于某一index的存储，中心缓存会记录内存块与页批量的映射关系，当某一内存块被返回时，将其放置在空闲链表中，并与原属于相同页批量的内存块放在一起。

（2）中心缓存->页面缓存

中心缓存释放时机：同样地，当某一index下的内存块过多时，释放；但中心缓存释放的单元是页批量，也即分配时从页面缓存拿到的是多大，返回时也是多大，这个过程需要多个map/set进行维护。

页面缓存接收：当拿到某一页批量时，会查找该页批量是否有空闲的相邻页批量，若有，则进行合并，便于更大的存储空间请求需求，减少页碎片的产生。
